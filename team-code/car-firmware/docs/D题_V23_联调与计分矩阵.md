# D 题 V2.3 联调与计分矩阵

> **版本：2026-08-01。** 本表用于把“已写入固件”“台架观察到”“现场闭环通过”分开记录。通信字段、时隙和评分原文以 `D题_通用通信与接口规范_v2.3.docx` 与 `D题 回复.txt` 为准。

## 1. 权威边界

| 项目 | 车端可以做 | 车端不能做 |
| --- | --- | --- |
| 启动与循迹 | PG13/PG9 物理起步、灰度循迹、编码器/JY901 辅助、本地安全停机 | 由地面站无线按钮启动、凭 ACK 停车。 |
| 坐标 | 接收 Pi 的合规 `FIELD_GLOBAL` 位姿，发布平台中心 `CAR_POSE` | 用雷达原点/车角替代平台中心；重复叠加装配偏移。 |
| LoRa | 发送 `0x80/0x81/0x84/0x85`，接收并校验 `0x82/0x02/0x83` | 改写在线 Version `0x02`，占用空中端/保护时隙。 |
| 飞机协同 | 以匹配阶段选择速度包络 | 生成 `ModeSeq`，发送相机模式/动作帧，决定投掷或降落。 |
| 校准 | 停车态接收、转发 Pi、Pi 成功后确认 | 运行中重置坐标，替代 Pi 的坐标转换责任。 |

## 3. 分层联调矩阵

| 层级 | 前置条件 | 操作 | 合格观察 | 必存证据 | 失败时先查 |
| --- | --- | --- | --- | --- | --- |
| L0：烧录/静态 | SWD、COM13 正常 | 烧录后发 `P` | 配置、引脚、任务状态可回读 | J-Link 输出 + `P` 原文 | 配置是否为 `LineFollowMissionDebug`，串口是否 115200。 |
| L1：传感器 | 车轮架空或安全场地 | 灰度逐头、JY901 新鲜度、编码器正反计数 | X1–X8 映射正确、中心 0x18、航向不陈旧 | 灰度日志、P/H | 4051 地址线、PG0 极性、USART2 是否误占 PA2/PA3。 |
| L2：本地路线 | 无线可断开 | 两任务从 A 起步并跑 A→B→C/D→A | 20 s 后启动；宽点不终止；A 返回准确停 | 每轮 `F`、A→B 实测时间、场地备注 | 先查编码器/灰度/航向，再查雷达。 |
| L3：恢复/急停 | L2 基础稳定 | 快包络短丢线、无人机起降扰动、再按任务键、运行守护 | 单/双帧原始全白不进 `LOST_HOLD`；三帧后才以方向历史和限幅 JY901 阻尼恢复；12 s、二次按键等安全停 | 对应 `F`（`raw/stable/lost_confirm/lost_yaw_recovery`）与急停发帧记录 | 灰度供电/阈值、JY901 新鲜度/方向、中心去抖、STBY、安全状态。 |
| L4：位姿/校准 | Pi 与雷达链路正常 | 停车校准，核对 0x80 与平台中心 | 校准 ID 非零、坐标/yaw 有效、≤250 ms；断位姿不阻塞本地起步 | Pi ACK、H、地面站截图仅作辅助 | 坐标系、单位、偏移所有权和 UART4。 |
| L5：车机阶段 | L2/L4 均稳定 | 同 MissionId 注入/执行任务一、二空中阶段 | 仅规定阶段解锁；超时/ACK/FOLLOW 不误动作 | 同轮 H + F + 飞控日志 | 任务身份、阶段映射、0x81 ACK 前置。 |
| L6：正式演示 | L0–L5 有证据 | 全链路跑题目要求流程 | 每个评分项都有可回放证据 | 统一批次目录、视频/时间/日志 | 不以单一 UI 成功提示判定。 |

## 4. 任务一与任务二阶段门

| 任务 | 本地启动后 | 禁止加速的输入 | 唯一空中解锁条件 | 解锁后状态丢失 | `ABORT` |
| --- | --- | --- | --- | --- | --- |
| 任务一（投掷） | 150 mm/s 协同速度 | 任务 ACK、`FOLLOW`、本地 C/D、地面站 UI | 同任务身份先经过 `DROP_ACTION`，再进入 `RETURN_HOME` | 保持已锁存快包络 | 回落协同速度，不自动停车。 |
| 任务二（动态着陆） | 170 mm/s 协同速度 | 任务 ACK、`FOLLOW`、原始 C/D 宽点、非匹配任务状态 | 同任务身份 `PLATFORM_TAKEOFF(10)`（或后续阶段），**或**本地 D 已同时达到 4650 mm + 1500（0.1°）累计转角 | 保持已锁存快包络 | 空中阶段解锁会回落；本地 D 解锁跨空中 `ABORT` 保持，不自动停车。 |

`MISSION_STATUS(0x82)` 是一次性阶段变更权威；`FLIGHT_TELEMETRY(0x02)` 只在本任务请求已获 ACK 后用于连续状态恢复。两者均不得改变小车启动/停机所有权。

## 5. 地图与最终 A 判据

- B、C、D 均是宽黑点；它们可被灰度识别为特征，但不能等价为任务结束。
- D→A 有弧度，累计 yaw 并不一定达到旧的单一大阈值。因此使用**起始航向接近**和**编码器累计距离**共同决定进入 A 接近区。
- 最终 A 停机须同时满足 `run_distance_mm ≥ 8800`、`a_heading_near_start=1`，并有：全黑、稳定 7 路灰度，或“中心灰度 + 已准备雷达中心”之一。
- 雷达是冗余辅助。雷达无效、延迟或漂移时，编码器与灰度链仍必须使小车安全停下。

## 6. 证据命名与判定模板

每轮保存为同一时间戳，例如：

```text
logs/20260801-153000_task1/
  flash.txt                 # 构建配置与 J-Link verify
  p_before.txt              # 起步前 P
  h_radio.txt               # 通信/阶段 H
  frozen.log                # F 原始冻结输出
  frozen_analysis.txt       # 脚本分析结果
  field_note.md             # 场地、线宽、接线、人工观察
```

`field_note.md` 必填：任务号、起步时刻、A→B 时间、是否见到 C/D、A 点停机点、终止原因、是否有飞控阶段、是否发生人工干预。任何一项缺失时，最多只能称“部分观察”，不能标记为该矩阵“通过”。
