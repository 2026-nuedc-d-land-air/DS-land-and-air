# D 题任务一/任务二雷达协同联调

> 本文是**现场操作顺序**，不是协议原文。先跑单车，再加雷达/Pi，再加入无人机；任一层不稳定时退回上一层，保留原始日志后再修改。

## 1. 开机前 60 秒检查

1. 抬轮或将车置于安全起点；确认前驱 STBY、电机供电、编码器和 JY901 接线。
2. 确认灰度模块 `PC0/PC1/PC2 → AD0/AD1/AD2`、`PG0 ← OUT`；A 点为全黑/允许中心灰度，B/C/D 为宽黑点。
3. 打开 `COM13`（115200 8N1），先保存启动串口输出；不要只看地面站。
4. 执行 `P` 并核对：20 s 本地起步、T1/T2 `150/170`、A 返回 `8000/8800/±300`、丢线 `1400/5/12 s`。
5. 使用 `H` 检查 LoRa 的任务身份、接收计数和位姿新鲜度；雷达/Pi 未就绪时仍可做纯本地循迹。

命令见 [`line_follow_uart_flash.md`](line_follow_uart_flash.md)。每次重上电、重插串口或改接线均从这五项重新开始。

## 2. 分阶段流程

### 阶段 A：小车单机（必须先通过）

| 步骤 | 操作 | 应看到什么 | 失败处理 |
| --- | --- | --- | --- |
| A1 | 仅小车、无雷达/无人机；从 A 按 PG13 或 PG9 | A 点确认后电机仍关闭，20 s 后直接起步 | 先查按键消抖、灰度 A 点与 JY901 新鲜度；不要等 FOLLOW。 |
| A2 | 完成 A→B 时间试跑 | T1 150 / T2 170 基准，实际 <15 s 有裕量 | 校准编码器/基础速度，不能用空中状态掩盖超时。 |
| A3 | 继续经过 B/C/D | 宽黑点不会当成最终 A 而停车 | 记录对应 `F` 的里程和灰度掩码，先查距离门。 |
| A4 | D→A 真实弧线 | 任务二到 8000 mm 即预减速至 170 mm/s；任务一仍需航向回初始 ±30°；最终 A 停下 | 若越过 A：先看 `a_heading_err`、路程和稳定掩码，再校验灰度。 |
| A5 | 制造短丢线 | 以历史方向搜索，中心捕获后平滑恢复 | 若 12 s 停机，保留 `F`，检查方向历史/线宽/速度。 |

单机没有稳定前，**禁止**把雷达阈值或无人机模式作为修复手段。

### 阶段 B：雷达/Pi 位姿

1. 在小车停止时进行校准；确认位姿是 `FIELD_GLOBAL`、平台中心、`CalibrationId≠0`。
2. 记录 `H`：位置/yaw 有效、年龄 ≤250 ms、`CAR_POSE(0x80)` 在位姿新鲜时约 10 Hz。
3. 断开或冻结 Pi 位姿做对照：小车仍应可从物理键本地起步和循迹；只是不发送合规协同任务/坐标辅助。
4. 若坐标与车体不一致，先判定偏移由 Pi/空中端还是小车端拥有。当前车端前向偏移为 0 cm，禁止双方同时加 `+13 cm`。

### 阶段 C：无人机/LoRa 阶段联调

1. 固定一次 `MissionId`，记录任务类型、序列号和校准 ID；车机双方必须完全一致。
2. 发起任务后确认车端只在有效校准出现时请求 `0x81`，并且重试不重新触发本地电机。
3. **任务一：** 分别观察 ACK、`FOLLOW`、`DROP_ACTION`、`RETURN_HOME`。前两者不能加速；只在 `DROP_ACTION` 之后进入 `RETURN_HOME` 才能解锁。
4. **任务二：** 分别观察 ACK、`FOLLOW`、`PLATFORM_TAKEOFF(10)` 和本地 `d_reached`。前两项均不能加速；匹配 `PLATFORM_TAKEOFF(10)`（或后续阶段）可解锁。空中信息未到时，只有日志确认的本地 D（4650 mm + 1500（0.1°）累计转角）可作为后备解锁，原始 C/D 黑点不能解锁。
5. 解锁后短暂丢失空中状态，车端应保持已锁存包络。任务二若由本地 D 解锁，后续空中 `ABORT` 也必须保持；若由空中阶段解锁，`ABORT` 才回协同速度。无论哪种情况，除本地安全事件外不得停车。
6. 运行结束立即执行 `F`，并同时保存飞控 ESP32 串口日志。没有两端原始日志，不认定为车机通信成功。

## 3. A 点停车的排查顺序

当出现“D→A 过 A 不停”或“过宽点误停”时，按以下顺序定位：

1. `F` 中的 `run_distance_mm` 是否已达 8800 mm；未达时应当不停止。
2. `a_heading_near_start` 是否为 1；为 0 时查看 `a_heading_err` 和 JY901 新鲜度，确认弧线后的起始航向回归。
3. 检查灰度：是否有全黑、稳定 7 路或中心灰度；确认实际 A 点宽度和传感器高度。
4. 最后才查雷达中心辅助；它只在中心灰度存在时参与，不能把雷达噪声升格为停车条件。
5. 若 8000 mm 后仍高速，核对 `P` 的接近策略与当前编译镜像；不要用旧日志推断新参数。

## 4. 串口冻结日志验收

每轮最少采集：

```text
启动/参数：P
无线与阶段：H（必要时连续采样）
本轮结束：F
两端通信：小车 COM13 完整输出 + 无人机 ESP32 完整输出
```

`F` 应至少包含终止原因、任务/阶段、运行距离、灰度状态、yaw、丢线状态和 A 返回字段。推荐操作：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\dump_line_follow_frozen_log.ps1 -PortName COM13
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\analyze_line_follow_frozen_log.ps1 `
  -Path .\logs\<timestamp>.log
```

一次有效结论必须写明：“哪个任务、哪个 MissionId、哪一段加速/未加速、对应的空中阶段、最终终止原因”。`ACK timeout`、地面站“无人机无效”等 UI 现象只能作为线索，不能取代两端日志。

## 5. 故障隔离表

| 现象 | 首要检查 | 不应采取的做法 |
| --- | --- | --- |
| 20 s 后不动 | `P` 的启动状态、A/JY901 门、PG13/PG9 事件 | 盲目等待无人机 FOLLOW 或反复发送无线起步。 |
| 到 C/D 就加速 | H 中的匹配阶段、任务身份、本地调试标记 | 将 C/D 黑点直接当作阶段授权。 |
| 已投掷/停机却不加速 | 飞控是否发出规定阶段，0x81 ACK 前置是否满足 | 用单个 ACK 强行解锁。 |
| A 点未停 | 编码器 8800、起始航向、7 路稳定灰度 | 先调雷达距离或删除安全门。 |
| 中途循迹偏出 | 灰度掩码、历史方向、曲线速度、编码器反馈 | 将雷达坐标直接注入横向控制。 |
| ESP32 不能读串口 | 先留存/导出冻结日志与复位时间点 | 无证据地认定“通信成功”。 |

将同轮 `flash.txt`、`P/H/F`、小车/ESP32 原始串口、场地说明和视频时间点放入同一时间戳目录。然后在 [`D题_V23_联调与计分矩阵.md`](D题_V23_联调与计分矩阵.md) 标记实际达到的层级；没有原始证据的项目保持“待实测”。
