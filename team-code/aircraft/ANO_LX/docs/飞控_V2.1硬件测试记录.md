## 1. 本轮只测什么

以下基础能力已由既有测试覆盖，本轮**不重复测试**：手动遥控飞行、基础自主定点、普通起飞降落、常规姿态/位置 PID。

本轮只验证 V2.1 任务改造新增或风险最高的链路：

1. 飞控对激光、小车位姿、相机末段偏差的物理语义是否正确；
2. 自动任务是否只会在安全前提满足时起飞；
3. 投放和动态着陆两个末段任务能否正常完成；
4. STOP、传感器失效和未锁定等关键异常是否能安全收尾。

测试原则：先拆桨完成第 2、3 节；带桨后按第 4 至第 7 节逐项测试。任一项失败，停止向后推进并记录问题。

### 1.1 2026-07-30 相机—飞控投放台架测试（通过）

本项为拆桨台架联调，只验证飞控与 MaixCAM2 的 V2.2 串口会话、
投放命令和舵机动作；不代表自动起飞、飞行投放或返航流程已通过。

| 项目 | 实测配置/结果 |
| --- | --- |
| 飞控侧接口 | `USART3`，115200、8N1 |
| 相机侧接口 | MaixCAM2 `UART1`：A31=`UART1_RX`、A30=`UART1_TX`，设备 `/dev/ttyS1`，115200、8N1 |
| 物理接线 | 飞控 TX → A31；飞控 RX ← A30；两端共地、3.3 V UART 电平 |
| MODE 握手 | 飞控以 500 ms 周期发送 `CAMERA_MODE`；相机完成会话切换后返回 4 B 通用 ACK，测试通过 |
| 投放触发 | 相机返回 20 帧匹配会话的 `CAMERA_TARGET` 后，飞控仅发送一次 `CAMERA_ACTION/DROP`，测试通过 |
| 动作确认 | 相机先返回 ACTION ACK，再驱动舵机；`CAMERA_ACTION_RESULT` 按 12 B 布局返回，舵机实际完成投掷 |

相机端修改位于 `../相机代码/main.py`：显式将 A31/A30 复用为
`UART1_RX/UART1_TX`，使用 MaixPy `uart.UART('/dev/ttyS1', 115200)`；
ACK Payload 固定为 `RequestType, RequestSeq, Result, Detail` 四字节；
ACTION_RESULT 采用 `Action, Result, ActionId, SourceTimeMs, TaskType,
MissionId, ModeSeq` 共 12 字节布局。

本次台架曾临时启用 `CAMERA_BENCH_TEST_ENABLED=1`：飞控上电后自动建立
投放会话、等待 MODE ACK，并在满足 TARGET 帧计数后下发一次 DROP。该临时
逻辑及其专用仿真已从比赛版本移除；正常任务固件不再主动发送固定周期的
相机 MODE/ACTION。若需复现本项台架测试，应从 Git 提交 `adc8f57` 检出独立
测试版本，而不是在比赛工程中长期保留该状态机。

### 1.2 动态着陆控制链路拆桨台架测试（进行中）

> 目的：在不装桨的条件下，优先验证“地面站小车位姿/相机目标 → 飞控任务
> 状态机 → 飞控 `0x41` 实时控制帧”的方向、限速和异常收敛。首轮只覆盖
> `DYNAMIC_LAND`；不以此代替带桨的飞行性能、真实下降、触地或动态着陆验收。

#### 适用边界和安全要求

- 机体必须拆桨；投放物和舵机动作须机械隔离，不执行真实投放。
- 优先用支架、吊带或两人协作稳定机体；手持仅用于小幅、可控地模拟位移，
  不得以手持方式替代实际起飞、下降或触地验证。
- 一人专职保有遥控 STOP/模式切换和断电处置权；任一异常、方向不确定或
  机体失控趋势出现时，立即 STOP 并结束本条。
- 只有任务确实进入相应状态时才记录控制帧；不得通过修改代码、伪造 ACK 或
  强制状态跳转来将本测试判为通过。

#### 观测分工与记录方法

`0x41` 为飞控配套无线数传/私有上位机协议，当前无法由测试脚本直接读取。
测试人负责人工观察并记录该帧中 `vx`、`vy`、`vz`、`yaw` 四轴：记录方向
（`+`、`-`、`≈0`）和是否符合预期即可，无须抄录全部高频帧。

树莓派侧由 SSH 监视员在连接可用后核对地面站、小车、相机、网络和日志；
它不能替代或声称读取 `0x41`。每项先由监视员确认输入稳定，再由测试人施加
单一刺激并保持至少 3 s；记录同一测试编号、开始时刻和 `0x41` 观察结果，
便于人工关联两端日志。若树莓派 `192.168.0.133` 未能 ping/SSH 连通，则先
修复网络，不开始依赖地面站输入的项目。

| 测试编号 | 监视员确认的地面站输入 | 测试人观察的 `0x41` | 结果 |
| --- | --- | --- | --- |
| B-00 | Pi SSH、到相机的网络、小车位姿和相机目标日志均连续有效 | 上位机 `0x41` 可见，四轴读数稳定可辨 | 无需连接到相机网络，其余均正常；上位机0x41稳定可见。 |
| B-01 | 发起合法 `DYNAMIC_LAND` 请求，MODE ACK 与小车/相机数据有效 | 仅在任务进入相应状态后出现控制指令；不应因旧数据突然给出运动指令 | |

#### 2026-08-01 本轮拆桨记录

- 实际发起的是任务 1，状态机进入 `DROP_ALIGN`，因此本次为抛投路径的部分联调记录，不能替代本节 `DYNAMIC_LAND` 的完整验收。
- 已观察到 `CAMERA_MODE ACK`、飞控模式 2、飞控解锁，以及 `PRECHECK -> TAKEOFF -> INTERCEPT -> FOLLOW -> DROP_ALIGN` 阶段推进。测试人确认该过程中可见的 `0x41` 四轴读数与当前人工托举工况预期一致；尚未完成 B-L-02、B-L-03 的逐方向记录。
- 小车未放置目标靶。`DROP_ALIGN` 未取得满足有效、质量和居中条件的 `CAMERA_TARGET`，约 30 s 后上报 `0x5207 mission timeout` 并进入 `ABORT`，之后收到飞控一键降落接受事件并回到 `IDLE`。此结果通过了“无有效靶不进入动作阶段”的安全观察，不构成相机尺度、轴向或视觉闭环通过。
- 本轮随后收到小车 `MISSION_ABORT (0x84)` 的 `missionId=0` 接受回包；其出现时飞控已处于视觉超时后的 `ABORT`，所以未覆盖从正常任务阶段触发 STOP 的返航行为。该项仍按 B-L-08 待测。

#### 2026-08-01 任务一带桨记录

- 飞机正常起飞，在起点悬停约 3 s 后前往小车点；返航时高度恢复与降落过程符合预期。
- 旧实现进入平台上方时将 150 cm 到 135 cm 的高度目标按 1 cm/100 ms 分段下调，实飞观察到下降缓慢且有明显卡顿。本轮后续软件改为将阶段设定高度直接写入高度环；任务一在高位跟车稳定后再直接切换至 85 cm 投放高度。
- 任务停留在 `DROP_ALIGN`，相机日志记录 `DROP_ALIGN tt=2 mid=1` 后切回 `IDLE`；未观察到 `DROP_ACTION`。其行为符合末端放行条件未满足后的超时中止、返航路径。后续版本改为小车位姿主导放行，相机目标仅在有效时提供纠偏；相机链路中断仍禁止放行或继续下降。
- 此次记录验证了起飞、跟车、高度恢复和超时返航，不构成实际投放成功或动态平台着陆通过。

### 2.1 向下激光与平台几何

在机架、地面、平台三个位置读取至少 10 s 数据，确认 `fc_hight.alt_add` 的单位、增减方向、稳定性与 `alt_sta` 有效含义。

| 工况 | 实际激光到接触面距离 (cm) | `alt_add` 均值/范围 | `alt_sta` | 结论 |
| --- | ---: | --- | --- | --- |
| 地面静置 | 18 | 15~16 | 有效 | 使用仪器读数15 |
| 平台静置 | 到平台距离也为18 | 15~16 | 有效 | 使用仪器读数15 |
| 遮挡或断开激光 | 变为0 | 0 | 变为无效，传感器错误 | 使用仪器读数15 |

| 关键量 | 当前软件值 | 实测值 | 最终采用值 |
| --- | ---: | ---: | ---: |
| 地面悬停目标 | 150 cm | 150 cm | 150 |
| 平台上方悬停目标 | 135 cm | 136cm | 135 |
| 平台有效高度 | 15 cm | 14.5cm | 15 |
| 激光至接触面距离 | 16 cm | 18cm | |
| 着陆末端目标 | 18 cm | 18 cm | |

结论：距离增加时 `alt_add` `增加 `；有效 `alt_sta` 值：`始终有效`。
