## 当前结论

V2.2 地面站本地适配、远端部署和基础运行验收已完成。V2.2 保留 LoRa USB-TTL 接收、地图显示和校准维护；飞机 H 点、未校准小车 A 点的偏移仅在 UI 地图/文字显示中使用，校准和发送保持原始协议坐标。`CALIBRATION_SET` 实机 ACK 闭环、逻辑分析仪时隙测量和任务期 0 Hz 发射仍待验收。

V2.3 维护复位按钮方案已写入本地协议草案和补丁说明，尚未实现到小车、飞控、机载 ESP32 或地面站，也没有上传到树莓派。该方案只允许“物理按钮长按 + 小车静止至少 20 s”后清除旧校准；停车满 20 s 不会自动解锁。飞控重复上电而小车 Pi 未重启时，可继续复用同一套有效校准。

正式程序现在具备：

- V2.2 `AA 55`、CRC16/CCITT-FALSE、大端序和 100 ms 流式解析；
- `FLIGHT_TELEMETRY`、`CAR_POSE`、`CAR_TASK_REQUEST`、`MISSION_STATUS`、ACK 解码；
- 组委会 400×500 cm 净版场地图、飞机/平台中心、坐标/yaw、新鲜度、校准 ID、任务/阶段、错误和倒计时显示；
- 唯一的“起飞前校准”维护流程；
- `Seq mod 5=2` 后 30–50 ms（目标 35 ms）的一次性 `CALIBRATION_SET`；
- ACK + 相同 ID 的后续 `CALIBRATED FIELD_GLOBAL CAR_POSE` 闭环；
- READY、任务请求、任务状态、符合 `URGENT+ACK_REQUIRED` 的 `MISSION_ABORT`、非 IDLE 遥测或小车运行后的进程级永久发送熔断；
- 只接受 `FLIGHT_TELEMETRY` 和 `CAR_POSE` 的 `CoordinateFrame=FIELD_GLOBAL`；飞机 H 点、未校准小车 A 点固定偏移只用于地图/文字显示，校准和发送使用原始协议坐标；
- CH340 稳定别名、串口独占、DTR/RTS 禁用、断线重连、解析错误统计和只读探针。

正式程序不具备、也不得新增：

- RTSP、VLC、实时图传或任何网络依赖；
- 二维码/旧 `AA BB` 任务语义；
- 地面站启动、停止、降落、投放、任务选择或参数修改发送；
- 任务期心跳、ACK、自动校准重发或调试透传。

## V2.3 维护复位草案（未部署）

- 新增 `0x85 MAINTENANCE_RESET`，小车 `0x30` 向广播 `0x10` 发送；在线 `Version` 字段仍为 `0x02`；
- 物理按钮由小车 MCU 处理，要求连续静止 20 s 且长按 2–3 s；Pi 清除 `Δx/Δy`、`CALIBRATED`、`CalibrationId` 并 ACK 后，MCU 才连续三次广播该消息；
- 地面站未来收到消息后进入“维护复位待人工确认”，而不是自动恢复发射；
- 飞控任务中收到维护复位或后续未校准位姿必须中止/失效保护，不能借此恢复任务；
- 一次校准可跨两个任务复用的前提是小车 Pi 未掉电/重启、坐标轴和安装关系不变；飞控重启不清除该条件。

全端实现前需要完成：小车 Pi/MCU 本地握手与按键测试、LoRa 三帧重传和去重测试、ESP32 `SubType=0x05` 转发、飞控安全状态机测试、地面站人工二次确认 UI/串口测试。详细定义见 [V2.3_维护复位协议补丁.md](V2.3_维护复位协议补丁.md)。

## 历史 V2.1 COM6 模拟小车端到端测试

测试时间：2026-07-29。Windows `COM6` 为 CH340 + 同配置 LoRa，作为独立小车无线端，仅发送未校准、未运行的 V2.1 `CAR_POSE`；没有发送任务请求、校准或任何控制消息。该结果只保留为历史链路基线，不能替代 V2.2 验收。

### 30 秒负载与双向通信

| 项目 | 结果 |
|---|---:|
| 模拟 `CAR_POSE` | 300 帧 / 30 s，约 10 Hz |
| COM6 短写 | 0 |
| COM6 发送周期 | 平均 100.02 ms，范围 93–110 ms |
| 收到飞机 `FLIGHT_TELEMETRY` | 61 帧，约 2.03 Hz |
| COM6 接收解析 | CRC/长度/版本/地址/噪声错误均为 0 |
| 树莓派接收日志 | 约 12 Hz 合计负载，CRC/长度/载荷/未知/估计丢序均为 0 |
| 树莓派发送 | 0 帧；无 `CALIBRATION_SET` |
| 发送闩锁 | 未触发，`tx_locked=False` |

树莓派画面正确显示模拟车平台中心 `(100,100)`，以及飞机遥测约 `X=45 cm、Y=23 cm、Z=60 cm、yaw=-15.0°`；任务阶段为 `IDLE / 等待有效校准`。模拟停止后，飞机和小车链路均按阈值自动转为失效，历史坐标仍保留显示。

### 10 秒回应时延短测

发送 100 帧 `CAR_POSE`，其中 20 个 `Seq mod 5=0` 槽；收到 20/20 帧飞机遥测，解析错误为 0。

从 COM6 完成 `CAR_POSE` 串口写入到 COM6 完整收到飞机遥测的端到端时间：

- 最小 78 ms；
- 平均 91.6 ms；
- 最大 94 ms。

全部样本都在下一个 100 ms 车周期前完成，但最差样本只剩约 6 ms 保护。该测量包含“车模拟 LoRa 空中发送 + 飞机响应等待 + 飞机 LoRa 空中发送”，不能直接替代规范要求的“飞机收到 CAR_POSE 完成后 30–55 ms 发送窗口”测量。正式时隙验收仍必须用逻辑分析仪同时观察飞机端 LoRa UART 的接收完成和发送起止时刻，并扩大样本量计算 P99。

### H 原点偏置部署后复测

无人机每次在 H 圆心上电，飞控上报坐标以该点为局部 `(0,0)`。地面站已部署固定平移：

```text
X_FIELD = X_LOCAL + 113 cm
Y_FIELD = Y_LOCAL + 288 cm
```

其中精确 H 圆心为 `(112.5,287.5)` cm，整数值来自 V2.1 协议 1 cm 分辨率量化。转换在串口解码入口完成，转换后的坐标同时用于文字、地图和起飞前小车校准差值；Z/yaw 保持原值。

## 下一步实机验收

1. 按 V2.2 起飞前流程将无人机定位参考点与小车 A 点平台十字人工对准，确认收到的飞机/小车遥测均为 `FIELD_GLOBAL`；再分别向场地图上方和左方移动已知距离，确认 X/Y 正方向与比例。
2. 用逻辑分析仪测量飞机端 `CAR_POSE` 接收完成到 `FLIGHT_TELEMETRY` 发送起止，验证 30–55 ms 回应槽和 P99。
3. 用逻辑分析仪同时测量 `CAR_POSE` 接收完成与地面站 TX 起始，连续统计校准维护槽延时分布。
4. 注入 ACK 接受/拒绝/丢失和错误 CalibrationId，核对界面与发送次数。
5. 在 READY 和任务请求到达前后监测 TX 引脚，证明任务期持续 0 Hz。
6. 用 400×500 cm 实际场地核对原点、X/Y 朝向、边界和 yaw 箭头。
7. 连续 10 分钟运行 10 Hz CAR_POSE + 2 Hz FLIGHT_TELEMETRY，记录 CRC、长度、载荷、丢序和最长接收空窗。
