# D 题小车端实施基线

> **适用配置：** `LineFollowMissionDebug`（比赛循迹模式）。
> **用途：** 记录当前源码、接线和验收边界；“已实现”不自动等于“实机已验收”。

## 1. 责任与状态边界

小车负责物理起步、灰度循迹、前轮编码器闭环、JY901 航向辅助、Pi 位姿接入、LoRa 车端帧和本地安全停机。飞控负责空中任务、投掷/平台动作以及 MaixCam `ModeSeq` 会话。地面站负责显示和预飞校准。

```text
IDLE
  └─ PG13 / PG9 + A 点确认 + JY901 新鲜
       └─ 20 s 本地延时
            └─ 灰度循迹（本地始终拥有驱动权）
                 ├─ 有效 Pi 位姿：发布 0x80，按条件请求 0x81
                 ├─ 匹配空中阶段：仅解锁速度包络
                 ├─ D→A：任务二 8000 mm 编码器预减速；任务一保留编码器/航向预减速，灰度确认 A
                 └─ 安全事件：电机安全停机并冻结原因
```

无线 ACK、遥测过期和地面站 UI 不是本地停车条件。运行中再按 `PG13` 或 `PG9` 是急停，并发送紧急 `MISSION_ABORT(0x84)`；该行为优先于协同逻辑。

## 2. 当前硬件基线

### 2.1 前轮、循迹与按键

| 功能 | 引脚/外设 | 当前约束 |
| --- | --- | --- |
| 前左/右 PWM | `PA2 TIM2_CH3` / `PA3 TIM2_CH4` | 20 kHz；不可挪作 USART2 默认引脚。 |
| 前轮方向 | `PE2/PE3`、`PE4/PE5` | 与电机实际方向和编码器符号共同标定。 |
| 前驱 STBY | `PE6` | 复位、异常和切换时默认低。 |
| 前轮编码器 | `TIM5 PA0/PA1`、`TIM3 PA6/PA7` | 用于速度内环、里程门和 A 返回辅助。 |
| 灰度地址 | `PC0/PC1/PC2` | 74HC4051 式选通，`000..111` 对应 X1..X8。 |
| 灰度输出 | `PG0` | 单根数字 `OUT`；`PG1` 未使用。 |
| 任务键 | `PG13` / `PG9` | 低有效：任务一 / 任务二；运行中均急停。 |
| 维护键 | `PG12` | 停车态维护复位事件；不与任务二复用。 |

灰度已验证：白底掩码为 `0x00`、中心黑线为 `X4|X5=0x18`，X4 为车体左、X5 为车体右。控制误差使用固定的 `-7,-5,-3,-1,+1,+3,+5,+7` 诊断权重；每次更换模块或线序必须重跑 [`灰度循迹触发测试.md`](灰度循迹触发测试.md)。

### 2.2 串口与链路

| 链路 | 配置 | 用途与拒绝规则 |
| --- | --- | --- |
| USART1 | `PA9/PA10`, 115200 8N1 | 诊断，当前 `COM13`；保留为现场证据接口。 |
| USART2 重映射 | `PD5/PD6`, 9600 8N1 | JY901 航向；未新鲜时禁止起步。 |
| UART4 | `PC11` 接收，115200 8N1 | Pi `FIELD_GLOBAL` 位姿；旧 `FA...AB` 只显示，不参与协同。 |
| UART5 | `PC12/PD2`, 115200 8N1 | LoRa 透明传输；不得同时接 Pi/Nano。 |

Pi 位姿只有在位置、yaw、校准有效位真实且 `CalibrationId≠0` 时可用于协同；年龄超过 `250 ms` 即为过期。车端发布的是平台中心坐标，当前车端前向偏移默认 **0 cm**，不得与 Pi/无人机侧机械偏移重复叠加。

## 3. 循迹、速度和 A 点策略

### 3.1 起步与速度

- A 点全黑或允许的稳定中心灰度，且 JY901 新鲜，才可接受一次任务键。
- 按键后电机保持关闭 **20 s**，随后本地直接起步；不等待无人机跟随信息。
- A→B 基准：任务一 `150 mm/s`、任务二 `170 mm/s`。快包络为 `600/420/360/260/180/600 mm/s`（直线/缓弯/硬弯/急弯/丢线/宽线）。
- 任务一仅由匹配空中状态 `DROP_ACTION → RETURN_HOME` 解锁。任务二可由匹配 `PLATFORM_TAKEOFF(10)`（或后续空中阶段）**或本地验证 D** 解锁；本地 D 同时要求编码器路程 ≥4650 mm 和累计航向行程 ≥1500（0.1°），因此不是对 C/D 宽黑点的直接响应。`ACK`、`FOLLOW` 和原始宽黑点均不能加速。
- 合法加速后的空中状态暂时丢失仍保持该包络。任务二的**本地 D** 解锁是路线进度锁存，空中端后续 `ABORT` 不撤销它；任务一和任务二的空中阶段解锁收到 `ABORT` 才回落到协同速度。任何回落都不是停车命令。
- 任务二首次由 `PLATFORM_TAKEOFF` 或本地 D 解锁时，基础目标最多每 `20 ms` 上升 `70 cps`，以消除快包络切入的瞬态波动；曲线、丢线和 A 接近的降速不增加额外延迟，任务一不使用此门。
- 任务一在合法 `RETURN_HOME` 快包络后，编码器达到 `4650 mm` 即进入 D→A 稳态段：基础速度上限 `420 mm/s`。该门仅用于任务一，保留原有曲线档、`8000 mm + 航向` A 预减速和最终 A 判定。

### 3.2 丢线恢复

灰度原始全白不是立刻丢线：必须连续 3 次扫描确认，期间保留上一帧已稳定的灰度掩码、纠偏、速度档和 JY901 轨迹切线，过滤无人机起降振动、光照闪变或瞬时接触不良造成的单/双帧全白。确认后先朝**最后一个已稳定的非中心触发传感器**方向找线；只有没有有效边沿方向时才回退到最近四帧方向历史。历史/边沿方向提供 `1400 cps` 搜索差速，JY901 对上一条有效切线提供限幅 `±600 cps` 的反向阻尼；合成差速限幅为 `±1600 cps`，搜索速度 `180 mm/s`。首次有效中心捕获立即中和历史差速；连续 5 个 `20 ms` 中心样本才真正退出恢复，若中断则恢复原方向历史。连续确认丢线 `12 s` 停机并写冻结终止原因。冻结记录新增 `lost_confirm`、`lost_yaw_recovery`、`last_edge_gray_diff`、`lost_source`；`raw=0` 而 `stable≠0` 是被过滤的瞬态全白证据，`lost_source=1` 表示直接按最后边沿找线。

### 3.3 B/C/D 宽点与 D→A 停车

地图中 B、C、D 均为比循迹线宽的黑点，**不能**拿到全黑就停止。最终 A 采用多条件策略：

1. 编码器累计路程先达到 `8800 mm`；此前一律不得作为最终 A 停机；
2. D→A 是弧线。**任务一**从编码器 `4650 mm` 起将基础速度上限限制为 `420 mm/s`，避免快包络在首段浅弯的过冲；其原有 `8000 mm + 起始航向 ±30°` A 预减速仍保留。**任务二**达到 `8000 mm` 无条件限制到保守的 `170 mm/s`，避免该任务旧日志中 8189 mm 后的灰度/航向大差速交替。两任务在 `8800 mm` 均有后备接近限速；
3. 仅当路程门和起始航向附近同时成立，接受全黑 `A_MARK_RETURN` 或稳定 7 路灰度 `A_RETURN_GRAY_7BIT`；
4. 雷达只可在中心灰度已存在时提供 `A_RETURN_RADAR_CENTER` 辅助，不能脱离灰度/编码器单独停车。

冻结记录应输出 `a_heading_err` 与 `a_heading_near_start`。这取代了旧的“累计转角必须大于某固定值”的判断，以适配 D→A 的浅弧。

## 4. LoRa V2.3 协同边界

| 帧 | 车端行为 |
| --- | --- |
| `0x80 CAR_POSE` | Pi 位姿新鲜时 10 Hz 发布；是无线共享时间基，坐标为平台中心。 |
| `0x81 CAR_TASK_REQUEST` | 物理键选择任务后，等待有效校准再最多重试三次同一任务标识；本地循迹不因其等待。 |
| `0x82 MISSION_STATUS` | 只接受匹配任务号/任务类型；作为一次性阶段变更权威。 |
| `0x02 FLIGHT_TELEMETRY` | 只在本任务 `0x81` 已 ACK 后用于连续阶段恢复；不启动、不停小车。 |
| `0x83` 校准 | 仅停车态接收，向 Pi 转发；只在 Pi 成功后向地面站确认。 |
| `0x84 MISSION_ABORT` | 运行中第二次任务键立即停电机并发 3 次 ACK 要求帧。 |
| `0x85` 维护复位 | 满足停车维护条件时向地面站发 3 个规定帧；不清 Pi 保留校准。 |

在线帧 Version 固定 `0x02`。车端仅使用 0–25 ms 时隙发送姿态、任务重试或必要维护 ACK，30–55 ms 预留空中端，55–100 ms 保持静默；精确字段和重试规则必须以 `D题_通用通信与接口规范_v2.3.docx` 为准。

## 5. 运行证据和不得越过的结论

- `P`：读取固件参数、活动任务和安全状态；烧录后必做。
- `F`：冻结本轮运行关键事件；这是停机、丢线、A 返回和阶段门的主证据。
- `H`：通信收发计数、匹配性和时序；不是“任务成功”的单独证据。
- 只有在同一轮日志同时看到匹配任务身份、合法阶段、速度实际变化及完整运行结果时，才能称“车机加速协同已验证”。
- 后轮 TB6612 仍是独立台架映射；当前比赛镜像不应据此宣称四轮闭环已验收。

现场步骤、命令和故障隔离见 [`D题任务一二雷达协同联调.md`](D题任务一二雷达协同联调.md) 与 [`line_follow_uart_flash.md`](line_follow_uart_flash.md)。
