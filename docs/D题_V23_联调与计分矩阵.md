## 车辆控制权责

| 功能 | 主依据 | 雷达/Pi 角色 | 禁止行为 |
| --- | --- | --- | --- |
| 横向循迹 | 八路灰度 | 无 | 不用雷达 X/Y 直接转向 |
| 转弯航向 | 直接接入 JY901 yaw/yaw-rate | 无 | 不融合雷达 yaw 控制 |
| 速度与路径 | 前轮编码器、LADRC、灰度误差 | B/A 进度旁证 | 雷达不得单独加速或停车 |
| A 点停车 | 灰度 A 标记、累计航向、编码器路径 | 只预备回归窗口 | 雷达帧不得单独停车 |
| 无人机协同 | 合法 `0x81/0x82/0x02` 会话 | Pi 只单向提供原始位姿；MCU 本地校准后发布 `CAR_POSE/CalibrationId` | 无 Pi 时延后协同，不阻止车辆循迹或伪造 `0x81` |

失线后小车按最近四帧方向进入 `LOST_HOLD` 搜线；只有中心传感器捕获并连续 10 个
20 ms 控制周期（约 200 ms）稳定重获后才恢复，超过 12 s 才安全停止。内侧轮允许
有限反向目标扩大急弯差速，前轮编码器仍是速度反馈。

## 按键与安全

| 按键 | 当前行为 |
| --- | --- |
| PG13 | 任务一启动；运行中再次按下为物理急停 |
| PG9 | 任务二启动；运行中再次按下为物理急停 |
| PG12 | 当前标准：车辆停止后低有效短按（50 ms 消抖）即可清除本地校准并直接广播三帧 `0x85`；超过三帧发送窗口后可再次短按，生成新的 ResetId |
| PG10 | 不参与启动、停车或任务 |

正式镜像禁用串口 `S` 停车；串口 `P/F/H` 仅用于读取状态和冻结日志。安全急停必须
在证据中标明，不得混同为正常任务完成。

### PG12 维护复位标准

本工程只保留一种 PG12 物理触发语义：车辆未运行时低有效短按，经过 50 ms 消抖即发起
本地维护复位。MCU 清除本地 Delta、`CALIBRATED` 与 CalibrationId，随后在三个连续车端
时隙广播同一 ResetId/Seq/Payload 的 `0x85`；三帧完成后可再次短按。

权威 V2.3 附录中的“静止 12 s + 长按 2--3 s”是外部赛题条款，不是当前固件的可选
构建模式，也不会在本工程中与短按混写为默认行为。它与当前单向 `Pi TX -> MCU RX`
硬件下的复位所有权差异，继续在合规清单 G3 中单独记录；短按日志不得伪称为长按验收
证据。

## 雷达坐标与地图

下表是 Pi 本地原始地图/安装参考，不能直接称为本轮 `FIELD_GLOBAL` 绝对坐标。
每次 `0x83` 的 `DeltaX/DeltaY` 仅存入 MCU RAM，并且只用于 LoRa 出站坐标；
Pi 原始输入和 MCU 内部雷达辅助始终保持未校准值。现场证据必须同时记录
`CalibrationId`、Delta 与校准后的三帧出站位姿。

| 点位 | 本地参考 X (cm) | 本地参考 Y (cm) | 航向参考 | 车辆用途 |
| --- | ---: | ---: | --- | --- |
| A | 0.0 | 0.0 | 约 0° | 起跑与灰度终点参考 |
| B | -151.3 | -8.1 | 约 0° | B 进度交叉检查 |
| C | -165.7 | 150.7 | 约 180° | 路线显示/方向核对 |
| D | -16.5 | 164.2 | 约 180° | 路线显示/飞行阶段证据 |

B/C/D 几何与约 150 cm x 150 cm 跑道相符。雷达 B 辅助要求距起跑 A 至少 155 cm
且连续两帧；编码器约 1550 mm 是不依赖雷达的后备进度。二者都不直接停车。

当前硬件中 Pi 到 MCU 的 UART4 链路为 `Pi TX -> MCU RX`，只传送原始位姿。
本轮空侧坐标约定为 MCU 对 LoRa 出站 `CAR_POSE` 仅执行一次镜像和平移：

`X_lora = -(X_pi - 13 cm) + DeltaX`

`Y_lora = -Y_pi + DeltaY`

`yaw_lora = yaw_pi`

X 轴先减固定 `13 cm`，再镜像 X/Y，最后叠加 `DeltaX/DeltaY`；内部原始
Pi/radar 坐标、JY901 和编码器逻辑均不应用这些变换。现场要同时抓 Pi 输入帧和 LoRa 出站帧逐帧验证该
公式，不能只验证“校准前后差值”。Pi 不发送校准 ACK；`DeltaX/DeltaY/CalibrationId`
当前归 MCU RAM 所有。

## V2.3 协同与校准

| 消息 | 小车端行为 | 最低通过证据 |
| --- | --- | --- |
| `0x80 CAR_POSE` | Pi UART4 原始位姿 -> MCU -> LoRa；仅出站应用 `X=-(X_pi-13 cm)+DeltaX,Y=-Y_pi+DeltaY,yaw=yaw_pi`，车端 10 Hz 时隙 | 新鲜度、CRC/长度/乱序、`CAR_RUNNING`、原始/出站逐帧公式 |
| `0x81 TASK_REQUEST` | PG13/PG9 会话建立后，先成功发送 3 帧当前 `CalibrationId` 的 `CALIBRATED 0x80`，再在三个车端槽重发；本地已起步时这些位姿同时带 `CAR_RUNNING` | `0x80 x3 -> 同 Seq/Payload 0x81 x3 -> 空侧 ACK`、会话匹配 |
| `0x82` / `0x02` | 更新匹配会话的阶段与速度门 | Stage、ModeCode、SourceTimeMs |
| `0x83 CALIBRATION_SET` | 地面 -> MCU 本地 RAM -> 地面 ACK；停车时的新请求 Seq 可完整替换旧 Delta，不累加 | ACK、三帧同 ID 和坐标平移校验 |
| `0x84 MISSION_ABORT` | 二次任务键急停后紧急通知 | 三帧、ACK/超时记录，不延迟关电机 |
| `0x85 MAINTENANCE_RESET` | 停车后 PG12 短按，本地清除并三帧广播，不访问 Pi | 同 ResetId/Seq；地面站随后以新 Seq/CalibrationId 的 `0x83` 重校准 |

MCU 的协同就绪条件是新鲜的原始 `FIELD_GLOBAL` 位姿
`POSITION_VALID|YAW_VALID`，并且 MCU 本地已有固定非零的 `CalibrationId`。
入站 Pi 帧不需要、也不应承担 `CALIBRATED`。该条件用于可靠建立 `0x81` 和可选
雷达辅助，不是本地小车循迹启动条件。PG13/PG9 已进入本地循迹后才满足该条件时，MCU
可以补发 `0x81`，但不会重新启动、减速或停止车辆。旧 `FA...AB` 是原始位姿
迁移数据；只要新鲜度和本地校准状态满足，可用于出站显示，但不替代正式 V2.3 输入验收。

当前车端在任务会话内只对 UART5 成功送出的 `0x80` 计数；校准 ID 改变、位姿失鲜或
在前导中插入地面 ACK 时清零。达到三帧后才允许 `0x81` 入队，因此按键到首个任务帧
会增加最多约 300 ms，但本地电机不会等待。UART5 RX 使用中断环形缓冲，避免任务发送后
的诊断串口输出覆盖空侧 ACK 接收窗口。

## 速度、阶段与计时

| 项目 | 当前车端策略 | 必须留存的日志 |
| --- | --- | --- |
| 任务一 A-B | `130 mm/s` 协同包络 | `motion_start`、B、`0x81`/ACK、飞行阶段 |
| 任务一加速 | 过 B、见 `DROP_ACTION(6)`、进入 `RETURN_HOME(11)` 后 | `coord_speed_unlocked` |
| 任务二起步 | `150 mm/s` 协同包络；前轮 LADRC 正向上限 `55%`（任务一保持 `45%`） | `motion_start`、`task2_pwm_max_pct=55` |
| 任务二加速 | `LAND_ALIGN(7)`、`DESCEND(8)`、`ON_PLATFORM_5S(9)` 均低速；仅 `PLATFORM_TAKEOFF(10)` 后 | `flight_stage`、`coord_speed_unlocked` |
| 任务二 B | 前轮首次实际运动起算，15 s 内应到 B | `task2_b_within_15s` |
| 整圈 | 从 `motion_start` 起不超过 90 s | `lap_complete` 或 `lap_timeout` |
| 车辆卡滞 | 推进释放后连续 20 s 没有编码器里程增量 | `progress_timeout,NO_ENCODER_PROGRESS_20S` |

出现 `task2_b_late`、`task2_b_deadline_missed`、`lap_timeout` 或 `progress_timeout` 即为失败
证据。`motion_start` 由任一前轮编码器达到 200 cps 记录。20 s 无进展保护只处理卡滞，
不替代 90 s 整圈判据；这两种停车都不是成功完成证据。

### 飞行阶段加速防回归

每次空地联调前后执行下表，不以“收到了无线帧”替代实际速度门验证：

| 注入或观察条件 | 预期小车状态 | 必须记录 |
| --- | --- | --- |
| 错误 `Src/Dst`、TaskType 或 MissionId 的 `0x82` | 拒绝帧，保持 `coord_speed_unlocked=0` | `flight_rx_invalid` 或 `radio_ack_drop_count` 增加 |
| 任务一：B 前、或未见 `DROP_ACTION(6)` 的 `RETURN_HOME(11)` | 保持协同低速 | `radar_b_reached`、`flight_drop_action_seen=0`、`coord_speed_unlocked=0` |
| 任务一：过 B、`DROP_ACTION(6)` 后的 `RETURN_HOME(11)` | 解锁回程速度包络 | `flight_stage=RETURN_HOME`、`coord_speed_unlocked=1`、`coord_speed_unlocked,reason=FLIGHT_STAGE_GATE` |
| 任务二：`LAND_ALIGN(7)` 至 `ON_PLATFORM_5S(9)` | 保持协同低速 | `flight_stage` 与 `coord_speed_unlocked=0` |
| 任务二：`PLATFORM_TAKEOFF(10)` | 解锁回程速度包络 | `flight_stage=PLATFORM_TAKEOFF`、`coord_speed_unlocked=1` |
| 阶段流中断超过 1.5 s，或收到 `ABORT(13)` | 立即重新锁回协同低速，不因无线状态单独停车 | `coord_speed_relocked,reason=FLIGHT_STATE_STALE` 或 `flight_stage=ABORT` |

`MISSION_STATUS(0x82)` 是带 TaskType/MissionId 的阶段权威；`FLIGHT_TELEMETRY(0x02)`
以 ModeCode 持续刷新相同阶段。后者只有当前任务 ACK 已接受、或已收到匹配 `0x82` 后才
能更新速度门，避免无关联的 2 Hz 广播触发加速。

## 现场流程

### 本地无雷达循迹

1. 按 [默认 J-Link SWD 50 kHz 烧录步骤](line_follow_uart_flash.md#j-link-swd-烧录默认)
   烧录 `LineFollowMissionDebug`，确认 JY901 新鲜、灰度位于 A 全黑标记。
2. 关闭 Pi/雷达后按 PG13 或 PG9，应出现 `LOCAL_START_OK` 并继续循迹。
3. 保存灰度、JY901、编码器、失线恢复、A 点停车和 `lap_complete`。
4. 没有 `0x81` ACK、飞行阶段和空中录像时，这只能证明车辆循迹，不能计无人机分。

### PG12 / `0x85` 验证步骤

1. 先以串口 `P` 确认 `pg12_short_press_only=1`、`motors_enabled=0` 和
   `maint_broadcast_left=0`。该状态同时给出维护复位计数与最近结果。
2. 低有效短按 PG12 并等待消抖。日志必须出现
   `maintenance_reset_local_applied,reason=PG12_SHORT_PRESS`；无线侧必须收到三帧相同
   ResetId/Seq/Payload 的 `0x85`，后两帧仅有 `RETRANSMISSION`。
3. 三帧结束后确认 `maint_broadcast_left=0`，再次短按 PG12；新事务必须使用递增的
   ResetId。随后地面站以新的 `0x83` Seq 与新的 CalibrationId 重新写入实际 Delta。
4. V2.3 附录的静止/长按条款不对应当前固件分支；它与 Pi 清除/ACK 缺口一并在 G3
   中记录。不得把本步骤的短按日志标记为该附录条款的验收证据。
### 正式无线协同

1. 按键前完成 Pi 原始位姿、LoRa、飞控、机载 ESP32、地面站和平台预检；确认连续三帧
   原始位姿有效，并逐帧确认 `X=-(X_pi-13 cm)+DeltaX,Y=-Y_pi+DeltaY,yaw=yaw_pi`。当前单向 Pi
   只能做 MCU 本地兼容联调；要主张严格 V2.3 得分，Pi 必须完成 `0x83/0x85` ACK。
2. 只在 `CAR_POSE.Seq mod 5=2` 后的 30--50 ms 窗口发送 `0x83`，必须显式填写现场值：

   ```powershell
   .\scripts\test_line_follow_calibration_link.ps1 -WirelessPort COM12 -DiagPort COM13 -DeltaXCm <现场值> -DeltaYCm <现场值> -CalibrationId <非零ID> -Send
   ```

+

3. 脚本必须得到 MCU 直接返回的地面 ACK、三帧有序同 ID `CALIBRATED CAR_POSE`，
   且相对校准前出站帧的 X/Y 增量等于输入 Delta；任一失败先修 MCU `0x83`/LoRa
   链路，不等待或排查 Pi ACK。
4. 按 PG13/PG9 后归档 `0x81`、ACK、`0x82/0x02`、B/整圈计时、飞行视频和地面站截图。

## 证据归档

`video.mp4` 和 `acceptance.md`。`acceptance.md` 记录镜像 SHA、硬件版本、Delta、场地、
