# D 题赛题合规差距清单

> **用途：** 防止把“代码存在”或“单次 UI 显示”误报为赛题通过。本文只记录需补证据、需澄清或禁止声称的项目；完成后应附证据路径和日期，不直接删除历史判断。

## 1. 当前可确认的边界

- 小车采用物理键、八路灰度、编码器、JY901、Pi 位姿和 LoRa 的职责分层；无线不直接控制车轮启动/停车。
- 当前代码有 20 s 本地起步、任务一/二阶段速度门、丢线恢复、D→A 编码器/航向预减速和冻结日志字段。
- `P` 已可用于确认当前镜像参数；它不构成赛道、车机或评分验收。
- V2.3 通信原文以 `D题_通用通信与接口规范_v2.3.docx` 为准，在线 Version 为 `0x02`。

## 2. 必须补齐的证据

| 项目 | 现状 | 合格证据 | 当前禁止表述 |
| --- | --- | --- | --- |

## 3. 需要遵守的实现红线

1. 不得将雷达位姿直接作为横向循迹控制或独立停车信号；灰度、编码器和 JY901 是本地安全主链。
2. 不得把 B/C/D 的黑点、单个 ACK、`FOLLOW`、地面站 UI 当作加速授权。
3. 不得同时在小车、Pi 与无人机侧叠加同一机械偏移；当前小车为 0 cm 保守偏移。
4. 不得使用 PG9 作为维护键；运行中的 PG13/PG9 始终是急停。
5. 不得让 ESP32 的 NVS 冻结日志连续失败/重试占用启动关键路径；无人机侧日志方案需有容量边界和串口可导出证据。
6. 不得从历史 `logs/archive` 笔记回填当前参数；当前源码、P/F/H 和本目录基线优先。

## 4. 最小闭环顺序

1. 烧录并保存 `P`，确认当前镜像和参数；
2. 无雷达/无人机完成两任务单车 A→B→C/D→A 与 A→B 计时；
3. 完成短丢线恢复、12 s 超时、二次按键急停；
4. 完成 Pi 平台中心校准、0x80 频率与断链对照；
5. 同一 MissionId 下完成任务一空中阶段加速、任务二空中阶段加速和任务二本地 D 后备加速对照；
6. 导出小车 COM13 与无人机 ESP32 两端原始日志，逐项填入联调矩阵；
7. 仅对有证据的行标为“现场通过”。

## 5. 证据命名

```text
logs/<YYYYMMDD-HHMMSS>_task<N>_<layer>/
  flash.txt
  p_before.txt
  h_radio.txt
  frozen_car.log
  frozen_car_analysis.txt
  esp32_uart.log
  field_note.md
```

`field_note.md` 写清楚：固件配置/提交、接线、雷达/无人机是否接入、任务/MissionId、场地/线宽、实际时间、结果、终止原因和人工干预。无原始日志时，该项维持“待实测”。
