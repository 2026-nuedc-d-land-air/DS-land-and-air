# V2.3 校准链路集成说明

> **范围：** 本文只规定 STM32 小车如何接受、转发和证明校准；不替代 Pi 坐标解算，也不定义无人机相机/飞行流程。

## 1. 坐标合同

| 项目 | 当前车端要求 |
| --- | --- |
| 坐标系 | `FIELD_GLOBAL`；车体前方 `+X`、左方 `+Y`、yaw 逆时针为正。 |
| 参考点 | 小车平台中心，不是雷达原点、驱动轮轴或底盘角。 |
| 单位 | X/Y：cm；yaw：0.1°；速度存在时：cm/s。 |
| 有效条件 | 位置、yaw、校准有效位真实，`CalibrationId≠0`，位姿年龄 ≤250 ms。 |
| 车端修正 | 当前 `LINE_CAR_POSE_PLATFORM_FORWARD_OFFSET_CM=0`；Pi/空中端已拥有的机械偏移禁止再叠加。 |

在任一任务内必须维持同一个非零 `CalibrationId`。旧的 `FA...AB` 位姿仅用于显示兼容，不能成为协同发任务或 A 点辅助的依据。

## 2. 物理与软件所有权

```text
雷达/SLAM ──> Pi（坐标转换、校准保留）
                 │ UART4, PC11=MCU RX, 115200
                 ▼
STM32 小车（有效性检查、CAR_POSE、任务身份、局部循迹）
                 │ UART5, PC12/PD2, 115200
                 ▼
LoRa / 地面站 / 飞控
```

- Pi 负责把雷达/SLAM 本地值转换为 `FIELD_GLOBAL` 和平台中心；小车不猜测未校准坐标。
- 小车只在停止态处理 `0x83` 校准，向 Pi 转发并等待 Pi 成功确认；成功前不能向地面站宣称校准完成。
- 飞控只消费小车的任务/位姿协同信息，并独立管理空中相机会话；小车不得创建飞控 `ModeSeq`。
- Pi 位姿缺失时，小车仍可按物理键进行 20 s 后的本地灰度循迹；缺失只意味着停止发送合规 `0x80/0x81` 协同信息及取消坐标辅助。

## 3. 与 V2.3 帧的关系

| 帧 | 校准相关行为 |
| --- | --- |
| `0x83` Calibration | 仅停车态接收，严格校验后发给 Pi；Pi 成功 ACK 是车端回 ACK 的前置。 |
| `0x80` CAR_POSE | 仅在有效校准、新鲜位姿时以 10 Hz 发布，携带同一 `CalibrationId`。 |
| `0x81` CAR_TASK_REQUEST | 物理键先完成本地选择；当合规位姿可用时才把该校准身份带入任务请求，最多三次相同身份重试。 |
| `0x82/0x02` | 只匹配既有任务身份来恢复空中阶段；不得改写校准 ID。 |
| `0x85` Maintenance reset | 停车维护事件向地面站发规定帧；不通过 UART4 清除 Pi 中的保留校准。 |

在线 Version 保持 `0x02`。字段、CRC、具体 ACK 和时隙必须逐项遵守 `D题_通用通信与接口规范_v2.3.docx`，本文不复制或修改它。

## 4. 现场校准与回归测试

1. 小车停止、车轮安全；记录本轮 `P/H` 原文和 Pi 当前时间。
2. 执行规定的地面站/Pi 校准流程，记录生成的非零 `CalibrationId`。
3. 确认 H/串口中坐标、yaw、有效位和 age 均合理；用量尺或已知点检查平台中心而非雷达原点。
4. 确认 `CAR_POSE(0x80)` 在新鲜期约 10 Hz；断开 Pi 后该帧应停止，且本地按键起步仍可用。
5. 再次校准仅可在停止态进行；运行中尝试必须被拒绝/不改变当前任务坐标。
6. 选定任务后，核对全部 `0x81/0x82/0x02` 使用同一校准 ID 和 MissionId；运行结束导出 `F`。

## 5. 常见错误与修复边界

| 现象 | 合理检查 | 禁止的“修复” |
| --- | --- | --- |
| 无人机看见的坐标有固定偏移 | 核对平台中心定义、Pi 变换和是否有双重 +13 cm | 同时在小车、Pi、无人机各加一个偏移。 |
| 位姿常被判过期 | UART4 接线、115200、时间戳/发送周期、250 ms 统计 | 降低有效性要求后把旧坐标用于停车。 |
| 任务未向飞控发送 | 校准 ID、位姿有效位、任务键事件与重试计数 | 让地面站直接替小车启动电机。 |
| 校准后行驶异常 | 区分横向循迹和坐标辅助；检查灰度/编码器/JY901 | 把 Pi 横向误差直接注入电机控制。 |

## 6. 验收记录

一条“校准链路通过”记录至少包括：配置/提交号、接线、`CalibrationId`、平台中心对照点、串口 `H` 原文、Pi 成功 ACK、`0x80` 频率、断 Pi 后的本地起步对照，以及本轮冻结日志路径。缺少任一项时只能记为“接口观察”，不能标记为闭环通过。
