# 八路灰度循迹：74HC4051 地址扫描测试

> **适用模式：** `COMPETITION_LINE_FOLLOW` / `LineFollowMissionDebug`。本模块不是八路独立 ADC；它通过三根地址线选一路、由一根数字输出返回结果。

## 1. 当前接线与真值表

| MCU 资源 | 灰度模块端 | 方向 | 说明 |
| --- | --- | --- | --- |
| `PC0` | `AD0` | MCU → 模块 | 地址 bit0。 |
| `PC1` | `AD1` | MCU → 模块 | 地址 bit1。 |
| `PC2` | `AD2` | MCU → 模块 | 地址 bit2。 |
| `PG0` | `OUT` | 模块 → MCU | 当前被选探头的数字输出。 |
| `PG1` | — | — | 未使用，禁止视为额外灰度输入。 |

地址 `000..111` 顺序选择 `X1..X8`；每次扫描必须等待地址稳定后再采样 `PG0`。当前实测解码约定：白底为 `0x00`，黑线命中 X1..X8 分别为 `0x01/0x02/0x04/0x08/0x10/0x20/0x40/0x80`。如果模块输出极性变化，用 `raw_mask XOR all_white_mask` 修正后再作控制判断。

## 2. 已确认的几何语义

| 观察 | 当前结论 | 控制意义 |
| --- | --- | --- |
| 正常居中黑线 | `X4|X5 = 0x18` | 是横向误差零点与“中心捕获”参考。 |
| 车体左侧探头 | X4 (`0x08`) | 诊断权重为负。 |
| 车体右侧探头 | X5 (`0x10`) | 诊断权重为正。 |
| A 起点/返回点 | 可能出现全黑 | 需要结合任务状态、编码器和航向；不能仅看全黑。 |
| B/C/D | 宽黑点 | 可产生多位/近全黑，绝不可单独作为最终停车依据。 |

静态诊断权重为 `-7,-5,-3,-1,+1,+3,+5,+7`（X1→X8）。实际左右电机纠偏方向必须通过低速实车验证；传感器符号正确不自动保证电机方向正确。

## 3. 标准逐头测试

### 前提

- 车轮架空或关闭 STBY，避免扫描期间意外运动；
- 供电、公共地、传感器高度和电位器阈值稳定；
- COM13 为 115200 8N1，保存完整串口输出；
- 使用当前 `LineFollowMissionDebug`，不要用历史 PF 直连 ADC/灰度程序。

### 步骤

1. 在全部白底采样，记录基线掩码；若非 `0x00`，先排查极性、阈值、反光和线束。
2. 用不反光黑片依次覆盖 X1 到 X8，每次只覆盖一个头；记录地址、原始 bit 和最终 bit。
3. 对照真值表，确认没有镜像、跳号、双位或抖动；任一异常都先检查 AD0/1/2 线序。
4. 将真实黑线放在中心，确认稳定 `0x18`；再分别向车体左/右移动，核对 X4/X5 方向。
5. 低速上车测试，观察误差增大时是否向黑线回正。若反向，只修改电机控制符号或权重符号之一，并重做左右回归。

建议将原始串口保存为：`logs/gray_mux_<timestamp>.log`，使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\analyze_gray_mux_log.ps1 `
  -LogPath .\logs\gray_mux_<timestamp>.log
```

## 4. 运行态判据

| 情形 | 应有行为 |
| --- | --- |
| `0x18` 连续稳定 | 正常中心循迹；丢线恢复的中心捕获计数递增。 |
| 单侧少量位 | 按横向误差纠偏，速度由曲线档位限制。 |
| 宽黑点/多位 | 作为线宽或地图特征，保持循迹；B/C/D 不完成任务。 |
| 原始 `0x00` 持续 1–2 次扫描 | 保持上一次 `stable` 掩码和纠偏，不进入 `LOST_HOLD`；冻结记录应见 `raw=0,stable≠0,lost_confirm=1/2`。 |
| 快速包络短丢线 | 先按最后稳定的非中心触发传感器方向，以 1400 cps 搜索；无有效边沿才使用历史方向，并叠加 JY901 对最后有效切线的限幅 ±600 cps 阻尼；合成差速不超过 ±1600 cps。首次中心捕获清除历史差速，连续 5 个 20 ms 样本后恢复。 |
| 原始 `0x00` 连续 3 次扫描 | 确认丢线后才进入方向保持搜索；连续丢线 12 s 安全停机并写 `LINE_LOST_TIMEOUT` 冻结证据。 |
| 最终返回 A | 还需编码器 ≥8800 mm、航向回起始附近；全黑或稳定 7 路灰度才可完成。 |

## 5. 不合格表现与定位

| 表现 | 高概率原因 | 首个检查动作 |
| --- | --- | --- |
| 全白/全黑固定 | OUT 极性、PG0 接线、阈值或供电 | 逐头覆盖，记录原始 PG0。 |
| X 序号错位 | AD0/AD1/AD2 线序或地址延迟 | 按地址表逐一测，不要靠整车猜。 |
| 中心不是 0x18 | 传感器安装横向偏移、探头高度或线宽 | 重测中心和左右，再决定是否更新零点。 |
| 左右纠偏相反 | 电机方向或误差符号只有一端反了 | 低速单侧偏线回归，单次只改一个符号。 |
| 过 B/C/D 停机 | 将宽点当 A，或编码器/航向门失效 | 导出 F，先看里程门与 `a_heading_near_start`。 |
| A 点过冲 | 预减速/稳定度/实际线宽不匹配 | 保留 F，按编码器→航向→灰度→雷达顺序排查。 |

## 6. 结论边界

逐头测试通过只说明“传感器映射和静态极性正确”。循迹通过还需要低速回正、曲线、宽点、丢线和 A 返回的实车冻结日志。详见 [`D题小车端实施基线.md`](D题小车端实施基线.md) 与 [`D题任务一二雷达协同联调.md`](D题任务一二雷达协同联调.md)。
