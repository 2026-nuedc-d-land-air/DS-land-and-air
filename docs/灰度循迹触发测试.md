# 八路灰度循迹：74HC4051 地址扫描测试

本车使用 Yahboom `YB-MVX05-V1.0` 八路灰度模块。模块并非三路 ADC 加一路
数字输入，而是内置数据选择器：MCU 用三根地址线选中 X1--X8 中的一头，再从
一根 `OUT` 读取该头的**数字**状态。该模块的 `AD0/AD1/AD2 + OUT` 工作方式和
真值表可见 [Yahboom 8-channel module reference](https://rcdrone.top/products/yahboom-grayscale-line-tracking-sensor)。

蓝光版可用于白底黑线地图；安装高度先保持在产品给出的 `16--24 mm` 范围内，再按
本文件标定实际车体的读数极性。

## 当前引脚与真值表

| 模块针脚 | STM32 引脚 | 方向 | 作用 |
| --- | --- | --- | --- |
| `AD0` | `PC0` | GPIO 输出 | 通道地址 bit0 |
| `AD1` | `PC1` | GPIO 输出 | 通道地址 bit1 |
| `AD2` | `PC2` | GPIO 输出 | 通道地址 bit2 |
| `OUT` | `PG0` | GPIO 输入 | 所选通道的数字输出 |
| `5V/GND` | 5 V / 共地 | 电源 | 不能遗漏共地 |

`PC0/PC1/PC2` 以前被错误地按 ADC 输入读取；旧日志中的 `adc0/adc1/adc2` 是悬空
地址脚读数，不是八头的反射值，不能继续作为循迹映射证据。

| `AD2 AD1 AD0` | 所选物理头 | `raw_mask` 位 |
| --- | --- | --- |
| `000` | X1 | bit0 (`0x01`) |
| `001` | X2 | bit1 (`0x02`) |
| `010` | X3 | bit2 (`0x04`) |
| `011` | X4 | bit3 (`0x08`) |
| `100` | X5 | bit4 (`0x10`) |
| `101` | X6 | bit5 (`0x20`) |
| `110` | X7 | bit6 (`0x40`) |
| `111` | X8 | bit7 (`0x80`) |

`GrayTrackingDebug` 在每个 20 ms 采样周期内依次选择八个地址，并输出：

- `raw_mask`：八个头的原始数字值，bit0--bit7 对应 X1--X8；
- `active_mask`：当前 `raw_mask XOR all_white_mask`，因此不依赖模块的高/低极性；
- `stable_mask`：`active_mask` 连续一致 3 次后的去抖结果。

## 烧录与逐头测试

本固件先执行 `MotorSafe_InitOff()`；前后 TB6612 均关闭。

```powershell
.\scripts\jlink_flash_gray_tracking.ps1
```

1. 让 **所有八个探头位于白底**，在同一日志中发送 `W` 建立白底掩码。
2. 对 X1--X8 逐头执行：该头白底采样，再只将该头移到真实黑线采样。
3. `MUX_MAP_LOCAL_WHITE_BLACK` 中只有本头的 `SELECTED_BIT` 从白底 `0` 到黑线
   `1`，且两段均稳定时，才记录 `CHANNEL_SWITCH`。

示例（先建立白底，再测试 X1；所有命令均由上位机执行）：

```powershell
$log = '.\logs\gray_mux_x1_<timestamp>.log'
.\scripts\capture_gray_tracking.ps1 -PortName COM13 -Command W -Seconds 3 -OutputPath $log
.\scripts\capture_gray_head_phase.ps1 -PortName COM13 -Position 1 -Phase white -OutputPath $log
.\scripts\capture_gray_head_phase.ps1 -PortName COM13 -Position 1 -Phase black -OutputPath $log
.\scripts\analyze_gray_mux_log.ps1 -Path $log
```

对 X2--X8 继续使用同一白底基准或每次重新建立 `W` 基准；重建基准时必须保证八头
全部在白底。`1`--`8` 串口命令仅为人工位置标记，不参与模块选通。

## 验收与边界

- 只有完成 X1--X8 的 `CHANNEL_SWITCH` 映射后，才允许生成加权横向误差和接入循迹 PID。
- 若所有 `raw_mask` 永远相同，优先检查 `AD0/AD1/AD2` 线序、5 V 供电、共地和 3.3 V
  地址高电平是否被模块可靠识别；不要退回 ADC 阈值方案。
- `OUT` 是 5 V 供电模块的数字输出；现有 `PG0` 已被实机读取，但任何重接线前仍需
  确认没有把 5 V 送入不耐压的 MCU 引脚。
- 旧 `gray_mapping_20260730-*.log` 和 10:15--10:30 的逐头 ADC 记录只作“错误驱动
  已定位”的归档，不作为当前八路传感器有效性结论。

## 2026-07-30 实机验收结果

证据日志：`logs/gray_mux_retest_20260730-104601.log`。先让八头同时处于白底并发送
`W`，得到 `all_white_mask=0x00`；随后逐头移至黑线。X1--X8 均获得
`CHANNEL_SWITCH`，且黑线阶段只有对应位稳定置位：

| 探头 | 白底 `active_mask` | 黑线对应位 | 结论 |
| --- | --- | --- | --- |
| X1 | `0x00` | `0x01` | 已验证 |
| X2 | `0x00` | `0x02` | 已验证 |
| X3 | `0x00` | `0x04` | 已验证；复测未见 X4 串扰 |
| X4 | `0x00` | `0x08` | 已验证 |
| X5 | `0x00` | `0x10` | 已验证 |
| X6 | `0x00` | `0x20` | 已验证 |
| X7 | `0x00` | `0x40` | 已验证 |
| X8 | `0x00` | `0x80` | 已验证 |

该结果只确认“模块地址、MCU 引脚、通道位号、白/黑可分”均正确；尚未确认模块在车体
朝向下的左/右误差正负，且尚未允许电机参与循迹。

## A 点全黑起点区域（2026-07-30）

用户将整组探头置于 A 点起始的全黑区域后，采集
`logs/gray_mux_all_black_A_20260730-110324.log`。`K` 黑色快照和后续连续样本均为
`raw_mask=0xFF`、`active_mask=0xFF`、`stable_mask=0xFF`，因此全黑区域与全白背景
`0x00` 可稳定区分。

这只是赛道的视觉标记证据：若后续任务状态机需要识别 A 点，可使用“稳定全黑”作为
路径位置条件；**不能**以它替代车上实体按键的任务启动条件。当前 `GrayTrackingDebug`
只记录该状态，仍不驱动电机。

## 正常黑线居中零点（2026-07-30）

用户将正常黑线置于阵列居中位置（X4、X5 同时触发）后，采集
`logs/gray_mux_center_x4_x5_20260730-110625.log`。连续 24 条有效采样均为
`raw_mask=active_mask=stable_mask=0x18`，即 bit3 与 bit4 同时置位。

因此，当前地图与安装高度下的循迹零点定义为 `center_mask=0x18`。后续加权误差的
数值零点由 X4/X5 的对称权重产生。

## 车体左/右误差符号（2026-07-30）

在车头朝向不变的条件下，正常黑线向车体左侧偏移时，连续 23 条样本稳定为仅 X4：
`0x08`（日志 `logs/gray_mux_vehicle_left_x4_20260730-111544.log`）；向车体右侧偏移
时，连续 23 条样本稳定为仅 X5：`0x10`
（日志 `logs/gray_mux_vehicle_right_x5_20260730-111651.log`）。

因此固件的静态诊断权重固定为 X1--X8：`-7/-5/-3/-1/+1/+3/+5/+7`；
`err_x100 < 0` 表示黑线在车体左侧，`0` 表示 X4+X5 居中，`> 0` 表示黑线在车体右侧。
本阶段仅打印 `line_class`、`line_side`、`active_count`、`err_x100`；不输出 PWM 或
方向控制。`0xFF` 明确标记为 `A_MARK`，`0x00` 标记为 `LOST`，均不参与横向误差计算。

每次烧录或复位都会清除 RAM 内的白底基准。新镜像已在 2026-07-30 11:19 烧录验证，
烧录后必须先执行一次“八头全白 + `W`”，再采集上述误差字段；否则日志显示 `UNCAL`，
属于预期安全状态。

### 误差诊断回归结果

重新白底标定后，当前镜像的实机输出已回归：X4+X5 居中为 `LINE/CENTER/0`，仅 X4
（黑线在车体左）为 `LINE/VEH_LEFT/-100`，仅 X5（黑线在车体右）为
`LINE/VEH_RIGHT/+100`。对应日志见 `gray_error_diag_center_20260730-112143.log`、
`gray_error_diag_vehicle_left_x4_20260730-112215.log` 和
`gray_error_diag_vehicle_right_x5_20260730-112247.log`。因此现可记录可靠的横向误差；
尚不可直接使能循迹电机输出。
