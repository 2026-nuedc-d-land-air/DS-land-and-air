# 灰度循迹接口纠正与重新测试检查点（2026-07-30）

## 有效硬件事实

用户提供的实物图确认模块为 Yahboom `YB-MVX05-V1.0`。排针丝印为
`5V / AD2 / AD1 / AD0 / OUT / GND`，并带有 X1--X8 的地址真值表。
模块内置 74HC4051 风格的数据选择器：MCU 输出三位地址，模块在 `OUT` 输出被选中
探头的数字值。蓝光版可用于白底黑线地图。

| 模块信号 | MCU 引脚 | 当前固件方向 |
| --- | --- | --- |
| `AD0` | `PC0` | GPIO 输出，地址 bit0 |
| `AD1` | `PC1` | GPIO 输出，地址 bit1 |
| `AD2` | `PC2` | GPIO 输出，地址 bit2 |
| `OUT` | `PG0` | GPIO 输入，所选头数字输出 |

地址 `000`--`111` 依次选择 X1--X8；固件将八个输出汇成 `raw_mask` 的 bit0--bit7。
以“所有探头都在白底”时的 `all_white_mask` 为基准，`active_mask = raw_mask XOR
all_white_mask`，因此不需要假定模块输出高/低代表黑线。

## 已废止的错误解释

此前将 `PC0/PC1/PC2` 配置成 ADC 输入是错误驱动。于是旧日志的 `adc0/adc1/adc2` 是
地址脚浮空/偏置读数，不是 X1--X8 的反射强度；其 x1/x2/x3 判定和任何 ADC 阈值均
不能用于循迹 PID。原始日志保留，仅作问题定位证据。

## 已完成的软件修正

- `bsp_gray_tracking.*`：改为 AD0/AD1/AD2 地址扫描 + PG0 数字读取；不用 `Delay_us()`
  破坏 SysTick 时间基。
- `app_gray_tracking_test.c`：输出 `raw_mask`、相对白底的 `active_mask` 与去抖
  `stable_mask`。
- `scripts/analyze_gray_mux_log.ps1`：输出逐头 `CHANNEL_SWITCH` 判定。
- `GrayTrackingDebug` 构建通过：FLASH `6400 B / 512 KB`，RAM `2008 B / 64 KB`；
  入口仍先调用 `MotorSafe_InitOff()`，前后 TB6612 关闭。
